01

快速开始

先在平台“开放 API”页面为调用服务器创建密钥。密钥只完整显示一次，请存入服务器密钥管理服务或环境变量，不要写进前端代码和 Git 仓库。

  1. 创建至少包含 READ 的 API Key
  2. 将服务地址与密钥保存为环境变量
  3. 调用健康接口验证网络、TLS 与鉴权
  4. 按业务需要增加 PLAYBACK 或 CONTROL 权限
成功标志健康接口返回 {"ok":true,"status":"UP"}，响应头包含限流策略。

      

    


    

      02
身份认证
所有业务接口都在请求头中使用 Bearer API Key。密钥以 vhk_ 开头，平台仅保存 SHA-256 哈希，无法找回原文。

      
AuthorizationBearer vhk_your_api_key

      
1每服务一把密钥
按调用方隔离，便于独立撤销和审计。
2最小权限
只授予当前集成实际需要的 Scope。
3只经 HTTPS
公网调用必须使用 TLS，避免密钥明文传输。
4定期轮换
创建新 Key、切换调用方后再停用旧 Key。

    


    

      03
权限范围

      
READ设备、通道、平台状态、快照与规范所有 Key 默认包含
PLAYBACK发起点播、心跳、停止与媒体读取涉及媒体资源
CONTROLGB28181 PTZ 方向、变焦与停止涉及设备控制

      05
点播生命周期
点播不是单次请求。调用方需要维持会话，并在结束时主动释放资源。

      
1查询设备与通道GET /devices
→
2发起点播POST /play
→
3每 10 秒心跳POST /heartbeat
→
4停止点播POST /stop

      
超时回收调用方停止发送心跳后，平台会回收观看会话。不要依赖超时作为正常停止方式。

    


    

      
06
HLS 媒体鉴权
点播响应返回绝对 HLS 地址、playbackToken 与建议请求头。清单和每个媒体分片都必须同时携带两层凭据。
Authorization证明调用服务器身份
＋
X-Playback-Token绑定当前点播会话

      
HLS.js 请求头配置
const hls = new Hls({
  xhrSetup(xhr) {
    xhr.setRequestHeader('Authorization',
      `Bearer ${API_KEY}`);
    xhr.setRequestHeader('X-Playback-Token',
      playbackToken);
  }
});
hls.loadSource(hlsUrl);

    


    
07
HTTP / HTTPS 与 CORS
服务器 → 服务器
不受浏览器 CORS 限制。公网使用 HTTPS，内网可通过防火墙限制来源 IP。
浏览器 → API
需要把前端精确 Origin 加入 OPEN_API_ALLOWED_ORIGINS，不支持任意通配来源。
反向代理
转发 X-Forwarded-Proto 和 X-Forwarded-Host，或设置 PLATFORM_PUBLIC_URL。


    
08
状态码与排错
400参数错误或资源状态不允许操作检查 fields/message
401API Key 无效，或管理员会话缺失/过期检查 Authorization 或 Cookie
403Scope 不足，或缺少 ADMIN 角色 / CSRF Token检查当前鉴权模式
404设备、通道或点播会话不存在重新查询资源
429超过每 Key 每分钟请求限制遵循 Retry-After
5xx平台、设备信令或媒体服务异常指数退避并记录请求
